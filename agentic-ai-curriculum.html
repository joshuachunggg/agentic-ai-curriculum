Module 01
What Makes Something Agentic?
FOUNDATION
⏱ 1–2 weeks
Open Module →
Why this matters
Most teams waste months building sophisticated-looking automations that are still just pipelines. This module draws the hard line between the two — so you build the right thing from day one.
We start with the question that trips up most people: what actually distinguishes an AI agent from a workflow or a chatbot? This module builds the mental model that everything else in the curriculum depends on. You'll leave able to look at any AI system and classify it correctly — and understand exactly what you'd need to add to make it agentic.
Core Topics
  • The spectrum from static AI to full autonomy LLM API calls → chatbots → automations → agents → agent networks
  • The four pillars of agency: Perceive → Reason → Act → Learn Why each component is necessary; what breaks when one is missing
  • Linear automations vs. agentic loops Branching, tool use, state management, goal-directed behavior
  • The role of tools, memory, and planning What "tool use" actually means at the architecture level
  • Generative AI vs. agentic AI — key distinctions Content generation vs. goal-driven operation with real-world consequences
  • Real-world examples: what is and isn't an agent Case studies: customer service, coding agents, research agents, DevOps
Exercise
Given 10 AI system descriptions, classify each on the autonomy spectrum and explain what would need to change to make each one more agentic. Discuss as a group.
Module 02
How Agents Are Built: Architecture Patterns
CORE
⏱ 2 weeks
Open Module →
Key insight
There is no single "agent architecture." There are design patterns — each with tradeoffs. The best engineers pick patterns based on task complexity, not hype.
This module goes inside the machine. You'll learn the major architectural patterns used to build agents today — from the simplest ReAct loop to full orchestrator-subagent hierarchies — and understand when to reach for each one. Special attention is paid to the difference between single-agent and multi-agent designs, and why complexity should be justified by the task, not imported by default.
Core Topics
  • The ReAct pattern (Reason + Act) — the foundational loop How agents interleave thinking and tool use; when this is enough
  • Tool design: what makes a good tool for an agent Granularity, naming, error surfaces; the "fewer, sharper tools" principle
  • Memory architecture: in-context, external, episodic, semantic Short-term context vs. long-term storage; retrieval strategies (RAG)
  • Planning patterns: chain-of-thought, tree-of-thought, skeleton-of-thoughts When to use each; the tradeoff between latency and reasoning quality
  • Orchestrator vs. subagent roles How to decompose complex tasks; delegation and result synthesis
  • When NOT to use agents — the case for simplicity Latency, cost, and reliability tradeoffs; when a pipeline is the right call
  • The 12-Factor Agent principles Emerging best-practice checklist for reliable LLM-based agent applications
Hands-On Lab
Build a minimal ReAct agent from scratch (no frameworks) — just an LLM, a tool loop, and a stop condition. Understand the mechanics before abstracting them away.
Module 03
Context Engineering: The Skill That Replaced Prompt Engineering
CORE
⏱ 1.5 weeks
Open Module →
The 2026 shift
"Prompt engineering is about what you say. Context engineering is about what the model sees." — The AI practitioner community (X, 2025–2026) reached consensus: context quality is the primary determinant of agent performance.
The community consensus in 2026 is that prompt engineering, while still relevant, is no longer the bottleneck. Agents fail because their context is noisy, overloaded, or irrelevant — not because the prompt was poorly worded. This module teaches context as a finite, high-value resource to be engineered, not assumed.
Core Topics
  • What context engineering means — and what it isn't Beyond prompts: everything the model sees at inference time
  • How long contexts fail: dilution, attention drift, reasoning fatigue Why bigger context windows don't solve bad context design
  • Structuring agent context: system prompts, conversation history, injected state Role of the system prompt; how to encode agent persona, goals, and constraints
  • Dynamic context management: what to include, compress, or evict Summarization strategies; context pruning; prioritization techniques
  • RAG and retrieval-augmented agents — when it's right Vector stores, semantic search, hybrid retrieval; RAG vs. fine-tuning decision
  • Few-shot examples and structured outputs in agent context Using examples to anchor behavior; JSON mode and structured generation
Hands-On Lab
Take a failing long-horizon agent task and diagnose it as a context problem. Redesign the context architecture (what goes in, what gets summarized, what gets retrieved) and measure the improvement.
Module 04
Multi-Agent Systems & Orchestration
ADVANCED
⏱ 2 weeks
Open Module →
2026 reality
The competitive moat is shifting from smarter individual agents to coordination layers that manage fleets of agents as unified systems. MCP downloads hit 97M/month by March 2026 — from ~2M at launch 16 months prior.
Single-agent systems have real ceilings. This module is about what happens when you break tasks across multiple specialized agents — and the new class of problems that creates. We'll cover the emerging protocol standards (MCP and A2A) that are becoming the plumbing of the agentic internet, and the orchestration patterns that make agent fleets reliable and governable.
Core Topics
  • Why multi-agent? Parallelism, specialization, error isolation When complexity justifies the overhead; the selective-use principle
  • Orchestration topologies: hierarchical, peer-to-peer, market-based Planner-executor patterns; role specialization (researcher, critic, executor, evaluator)
  • Model Context Protocol (MCP) — deep dive Agent-to-tool communication standard by Anthropic; server/client architecture; why it matters
  • Agent-to-Agent (A2A) protocol — the interoperability standard Agent Cards, Tasks, Messages, Artifacts; how A2A + MCP are complementary
  • Shared state, conflict resolution, and communication overload Agents that contradict each other; cache coherence; message passing vs. shared environment
  • Coordination patterns that break at scale Tail latency; cascading failures; the "agent swarm" anti-pattern
  • "Agent factories" — the emerging pattern for knowledge work Coordinated production of complex deliverables; coding, research, and writing pipelines
Hands-On Lab
Build a 3-agent research pipeline: a Planner agent that decomposes a question, Researcher agents that work in parallel using MCP-connected tools, and a Synthesizer that assembles the final answer. Compare quality and latency vs. a single-agent approach.
Module 05
Production, Safety & Governance
ADVANCED
⏱ 2 weeks
Open Module →
Why this can't be skipped
A retail agent bought 10,000 shoes — no purchase limit, no confirmation required. A DevOps agent racked up $12,000 in compute in one night fixing a CI loop. Production without controls isn't a demo — it's a liability.
Agents in production behave differently than agents in demos. This module covers the full stack of controls — guardrails, human-in-the-loop design, evaluation, observability, and regulatory compliance — that separate a polished demo from a system you can stake your reputation on.
Core Topics
  • Controlled autonomy: the HITL design philosophy Human-in-the-loop is not about slowing agents — it's about deciding where autonomy is earned
  • Guardrail architecture: layered, parallelized, risk-matched PII scanning, toxicity, jailbreak detection, budget limits, scope limits
  • Least-privilege tool access Agents should only have the tools they need; scoped permissions; no arbitrary shell access
  • Confidence-based escalation Setting thresholds; synchronous vs. async approval patterns; when to route to humans
  • Evals: how to measure agent quality Task completion, faithfulness, hallucination rate, cost per task; building eval harnesses
  • Observability: traces, logs, replay Agent traces as first-class artifacts; debugging non-deterministic systems
  • Regulatory landscape: EU AI Act (Article 14, Aug 2026 deadline), enterprise compliance "I don't know why the AI did that" is now a legal risk; auditability requirements
  • Security: prompt injection, data exfiltration, adversarial inputs The unique attack surface of agents that have real-world tool access
Hands-On Lab
Given a deliberately unsafe agent (no limits, no guardrails), identify the failure modes and systematically add guardrails: scope limits, HITL checkpoints, an eval harness, and a trace log. Document what broke during each red-teaming round.
Module 06
Frameworks, Tooling & the Ecosystem
ADVANCED
⏱ 1.5 weeks
Open Module →
Choosing wisely
The framework landscape is crowded and noisy. This module helps you pick the right tool for the job — and understand when building without a framework is the better answer.
LangGraph, CrewAI, AutoGen, OpenAI Agents SDK, Salesforce Agentforce — the ecosystem has exploded. This module cuts through the noise, comparing frameworks on the axes that matter for production: control, observability, state management, governance fit, and production track record.
Core Topics
  • Framework comparison: LangGraph vs. CrewAI vs. OpenAI Agents SDK vs. AutoGen Architecture tradeoffs; control vs. abstraction; when each shines
  • When to use a framework vs. build from scratch Frameworks add abstraction — which is either leverage or a debugging nightmare
  • Building MCP servers: connecting agents to real tools Server structure, tool definitions, authentication, deployment; the MCP ecosystem
  • Model selection: when to use big frontier models vs. smaller domain-specific ones 2026 trend: smaller, fine-tuned models for specific agent tasks; cost and latency tradeoffs
  • Deployment patterns: cloud, edge, local (e.g. MLX on Apple Silicon) Infra tradeoffs; latency-sensitive agents; privacy-preserving local inference
  • Observability and eval tooling: Langfuse, Galileo, Braintrust, Phoenix The emerging market for agent monitoring; what good tooling actually provides
Hands-On Lab
Build the same agent task using two different frameworks. Write a brief comparison: what did each framework make easier? Harder? What would you use in production and why?

Staying on the Frontier
FRONTIER
⏱ Ongoing

The meta-skill
The field moves faster than any curriculum can. The goal of this final module is to make you dangerous at staying current — not just at following it, but at reading the field and knowing what's signal vs. noise.
This module is about the meta-skill: how to remain at the frontier of a field that is moving faster than any single person can fully track. We cover the information diet of leading practitioners, the emerging paradigms worth watching in 2026, and how to distinguish genuine capability jumps from rebranded hype.
Core Topics
  • Where the real information lives — and how to read it X/Twitter practitioners vs. conference papers vs. vendor blogs; who to follow and why
  • Distinguishing signal from noise in a hype-driven field Red flags: rebadged concepts, demos that don't work at scale, benchmark gaming
  • Emerging paradigms to watch: what 2026–2027 might bring Long-horizon planning, agent self-improvement, AI-native "frontier firms," neuro-symbolic hybrids
  • The "agent factories" vision and knowledge work disruption Coordinated agent fleets replacing multi-step knowledge workflows; implications for your organization
  • How to evaluate new models and capabilities quickly Running your own evals; not trusting benchmarks alone; practical capability testing
  • Building a learning system: internal knowledge sharing, running experiments How to create a culture of frontier awareness in your team
  • Recommended reading, accounts, and resources (curated 2026 list) Karpathy, Anthropic Engineering Blog, LangChain blog, AI Engineer Summit, practitioner X accounts
Ongoing Practice
Weekly 20-minute team sync: one person brings a new capability, paper, or practitioner insight they found that week. The group evaluates: is this signal or noise? How would it change what we're building?
Module 08
Capstone: Ship Aria v3
CAPSTONE
⏱ 4–6 hours
Open Capstone →
The deliverable
A working, observable, safe, multi-agent customer success system you could actually deploy — built in five sequential phases, each adding one architectural layer on top of the last.
Seven modules of theory. One deliverable. This capstone assembles everything — the ReAct loop, context management, multi-agent orchestration, guardrails, and evaluation — into a single coherent production system. No scaffolding. No stubs left as exercises. You ship it.
Five Phases
  • Phase 1 · Foundation: Wire the core ReAct loop Six tools, dispatch pattern, stop-condition logic — the loop all other layers depend on
  • Phase 2 · Context: Add rolling summarization Compress old turns via Haiku, inject structured state blocks, keep costs bounded
  • Phase 3 · Intelligence: Add COMPASS research subagents Two specialists run in parallel via asyncio.gather; Aria synthesizes before deciding
  • Phase 4 · Safety: Input/output guardrails + HITL tiers Injection detection, PII blocking, three-tier authority enforcement in code not prompts
  • Phase 5 · Evaluate: Build and run your rubric Eight test cases, five-dimension scoring rubric, pass/fail suite — know when you're done
Capstone Deliverable
An aria_v3/ directory with six Python files — all runnable, all tested. Score yourself against a 10-criterion rubric. Pass 8 of 10 to complete the curriculum.
